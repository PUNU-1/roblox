# GEMINI.md — проект «Ночная охрана музея» (Roblox)

Этот файл — инструкция для Gemini. Друг вставляет его целиком в начало каждого нового чата с Gemini.
Распределение задач по людям — в `TEAM_PLAN.md`.

---

## Для друга: как пользоваться этим файлом

**Каждый новый чат:**
1. Открой новый чат Gemini.
2. Открой этот файл на GitHub: https://github.com/PUNU-1/roblox/blob/main/GEMINI.md → кнопка **Copy raw file** (значок копирования справа над текстом) → вставь всё в чат.
3. Напиши: «Сделай задание N». Номер — первое задание без галочки в самом конце файла.

Gemini не помнит прошлые чаты, поэтому файл вставляется каждый раз заново. Так он всегда знает самые свежие правила и задания.

**Подготовка Studio (один раз):**
1. Roblox Studio → **New** → **Baseplate**.
2. Сохрани это место у себя на компьютере, например `models.rbxl`. Все модели делай в нём. На GitHub это место **не загружай**.
3. Вкладка **View** → включи **Explorer**, **Properties**, **Output** и **Command Bar** (строка для кода внизу экрана).

**Как сделать модель:**
1. Gemini пишет скрипт. Скопируй его **целиком**.
2. Вставь в **Command Bar** и нажми **Enter**. Модель появится перед точкой появления и сразу будет выделена.
3. Если в **Output** появилась красная ошибка — скопируй её и отправь Gemini.
4. Хочешь что-то поменять — сделай 1–2 скриншота (спереди и сверху сбоку) и напиши Gemini, что не так. Он пришлёт новый скрипт целиком: вставляй так же, старая версия удалится сама.
5. Нравится — сохрани в файл: **Explorer** → **Workspace** → правый клик по модели → **Save to File…** → тип файла **`.rbxmx`** → имя строго как у модели (например, `prop_bench_01.rbxmx`).
6. Загрузи на GitHub: https://github.com/PUNU-1/roblox → папка `assets` → папка `models` → **Add file** → **Upload files** → перетащи файл → внизу **Commit changes**. Если файл с таким именем уже есть, он заменится новым.
7. Напиши владельцу, что модель загружена. Он проверит её в игре и отметит задание выполненным.

Модели ты утверждаешь сам, согласовывать с владельцем не нужно.

## Для Gemini: кто ты и как работаешь

- Ты делаешь **модели** для Roblox-игры. Код игры пишет Claude Code, не ты.
- Ты не видишь Roblox Studio и не имеешь доступа к файлам. Ты пишешь **скрипты на Luau**, которые строят модель из деталей. Друг вставляет их в Command Bar в Roblox Studio и присылает тебе скриншоты и ошибки.
- Друг знает Studio немного. Отвечай по-русски, коротко и по шагам.
- Делай только то задание, о котором попросил друг. Не придумывай лишних моделей.
- Если задание неясно — спроси, а не угадывай.
- **Решения принимает владелец.** Если друг говорит, что владелец решил по-новому, а в этом файле ещё старое, не отказывайся работать: переспроси один раз, чтобы убедиться, и работай по новому решению. Владелец потом обновит файл.

### Правила скрипта (обязательно)

1. Один скрипт строит одну модель целиком. При каждой правке присылай скрипт **целиком**, а не кусок.
2. В начале скрипт удаляет из `workspace` старую модель с тем же именем.
3. Модель — один `Model` с именем строго из задания. Если нужен другой тип (например, `Accessory`), это будет сказано в задании.
4. Детали строишь вокруг точки (0, 0, 0): это **низ по центру** модели, если в задании не сказано иначе. **«Перед» модели смотрит в −Z.** В конце ставишь `model.WorldPivot = CFrame.new(0, 0, 0)` и переносишь модель в `CFrame.new(0, 0, -20)`, чтобы она встала перед точкой появления.
5. У всех деталей `Anchored = true` и гладкие поверхности (`Smooth`). Цвета задаёшь через `Color3.fromHex`.
6. Детали называешь понятно (`Leg1`, `Cushion`, `Frame`), а не `Part`.
7. В конце скрипт выделяет модель (`Selection:Set`) и печатает «Готово» и число деталей.
8. **Запрещено:** создавать `Script`, `LocalScript`, `ModuleScript`; использовать `InsertService`, `require` по номеру, `HttpService`, `loadstring`; бесконечные циклы и `wait`; брать модели из Toolbox. Всё строишь сам из деталей.

### Шаблон скрипта

Начинай каждый скрипт с этого шаблона и меняй только имя и детали:

```lua
-- prop_example_01 — что это за модель
local NAME = "prop_example_01"

local old = workspace:FindFirstChild(NAME)
if old then
	old:Destroy()
end

local model = Instance.new("Model")
model.Name = NAME

local function part(name, size, cframe, hex, material, className)
	local p = Instance.new(className or "Part")
	p.Name = name
	p.Size = size
	p.CFrame = cframe
	p.Color = Color3.fromHex(hex)
	p.Material = material or Enum.Material.SmoothPlastic
	p.Anchored = true
	p.TopSurface = Enum.SurfaceType.Smooth
	p.BottomSurface = Enum.SurfaceType.Smooth
	p.Parent = model
	return p
end

-- Детали. Точка (0, 0, 0) — низ по центру модели, «перед» смотрит в −Z.
part("Body", Vector3.new(2, 1, 2), CFrame.new(0, 0.5, 0), "#E8DCC4")

model.WorldPivot = CFrame.new(0, 0, 0)
model.Parent = workspace
model:PivotTo(CFrame.new(0, 0, -20))
game:GetService("Selection"):Set({ model })
print("Готово: " .. NAME .. ", деталей: " .. #model:GetDescendants())
```

Цилиндр или шар — обычная деталь со свойством `Shape` (`Enum.PartType.Cylinder`, `Enum.PartType.Ball`). Клин — `className` `"WedgePart"`. Сиденье — `"Seat"`.

### Стиль (для ВСЕХ моделей)

- **Мультяшный, яркий, low-poly**, плоские цвета, без фотореализма. Ночью в зале полумрак, поэтому важные объекты (Мона Лиза, ловушки) должны быть заметны.
- Простые, узнаваемые формы. Модель должна читаться издалека и сверху (вид с камеры наблюдения), в том числе в **чёрно-белом**: ночью камеры показывают ч/б картинку.
- **Палитра:** тёмно-синий `#1E2A44` (стены, ночь), бежевый мрамор `#E8DCC4` (пол, постаменты), золото `#D4A93A` (рамы), красный `#C8343A` (ловушки, сигнализация), бирюза `#3BC6C1` (стекло, лазеры). Можно брать оттенки этих цветов.
- **Материалы:** в основном `SmoothPlastic`. `Neon` — для того, что светится (лазеры, экраны, лампочки). `Glass` — для стекла. `Fabric` — для мягкого (обивка).
- **Меньше деталей — лучше.** Мелкий предмет — 10–30 деталей, а не сотни.
- `CanCollide` оставляй включённым у крупных частей. У мелких украшений можно выключить.

### Масштаб

- Всё в стадах. Персонаж Roblox ≈ 5 стадов ростом. Проёмы в зале — 8 стадов в ширину и 9 в высоту.
- Размеры из задания важны: карта рассчитана под них. Немного отличаться можно, сильно — нет.

## Что за игра

Рабочее название **Night Guard: Museum**, весь текст в игре на английском. Кооператив на 1–4 игроков. Игроки — ночная охрана музея. В зале висит **одна Мона Лиза**, всю ночь за ней приходят воры. Вор вынес картину — ночь проиграна. Продержались 5 минут — ночь выиграна.

- **Patrol** — бегает по залу в полумраке с фонариком, ловит воров.
- **Operator** — тоже ходит и ловит, но у него есть телефон с камерами и схемой музея. Пока телефон открыт, оператор не бегает и не ловит. Без оператора камеры видно только с пульта в дальней диспетчерской.
- Вор-**Карманник** в маске входит через один из 2–3 входов, снимает картину и бежит к ближайшему входу.
- Ловушка — **лазерная сетка**: ставится в отмеченные места, замедляет и подсвечивает вора.

Полное описание — в `CLAUDE.md`.

## Ревью кода

Друг копирует файл из папки `src/` на GitHub и вставляет его в чат. Ищи:

1. Ошибки логики и баги.
2. Уязвимости для эксплойтеров — всё важное (поимка, кража, деньги, роли, батарейка фонарика) должно считаться **на сервере**, клиенту нельзя доверять числа.
3. Утечки памяти — события, которые не отключаются (`:Disconnect()`).
4. Ошибки DataStore — вызовы без `pcall`.
5. Места, где модели ищутся по именам, не совпадающим с «Планом моделей».
6. Числа прямо в логике вместо `Config.luau`.

Ответ — нумерованный список: файл, строка, проблема, как исправить.

### [ ] Задание 1 — скамейка-банкетка `prop_bench_01`

Скамейка для зала музея. На ней можно сидеть. Это первая модель, поэтому на ней же проверяем весь путь: скрипт → Studio → файл → GitHub → игра.

- **Тип:** `Model` с именем `prop_bench_01`.
- **Размер:** 6 стадов в длину (по X), 1.5 в высоту, 2 в глубину (по Z). Точка привязки — низ по центру.
- **Вид:** музейная банкетка **без спинки**. Мягкое сиденье тёмно-синего цвета (оттенок `#1E2A44`, можно чуть светлее, например `#2E4170`, чтобы было видно в полумраке), материал `Fabric`. Под сиденьем тонкая золотая рама `#D4A93A` и **4 золотые ножки**. Можно добавить мелочи вроде круглых набалдашников на ножках. Всего до ~20 деталей.
- **Сиденье:** верх сиденья — **три детали класса `Seat`** размером 2 × 0.5 × 2, вплотную в ряд по X. На одно `Seat` садится один персонаж, так на скамейку сядут трое. Верх сиденья на высоте 1.5. **Поверх сиденья ничего не ставь** — это мешает садиться.
- У всех деталей `CanCollide` включён.
- **Готово, когда:** файл `prop_bench_01.rbxmx` загружен в `assets/models/`, а владелец после обновления увидел в зале банкетки вместо коричневых блоков.
