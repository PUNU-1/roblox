Этот файл — инструкция для Gemini. Друг вставляет его целиком в начало каждого нового чата с Gemini.
Распределение задач по людям — в `TEAM_PLAN.md`.

## Для друга: как пользоваться этим файлом

**Каждый новый чат:**
1. Открой новый чат Gemini.
2. Открой этот файл на GitHub: https://github.com/PUNU-1/roblox/blob/main/GEMINI.md → кнопка **Copy raw file** (значок копирования справа над текстом) → вставь всё в чат.
3. Напиши: «Сделай задание N». Номер — первое задание без галочки в самом конце файла.

**Дальше Gemini сам всё объяснит по шагам** — куда нажать, что вставить, что должно получиться. Если что-то непонятно или не получается, просто напиши ему об этом или пришли скриншот.

Gemini не помнит прошлые чаты, поэтому файл вставляется каждый раз заново. Так он всегда знает самые свежие правила и задания.

Ниже — подробные шаги. Их не обязательно запоминать: Gemini проведёт по ним сам.

**Подготовка Studio (один раз):**
1. Roblox Studio → **New** → **Baseplate**.
2. Сохрани это место у себя на компьютере, например `models.rbxl`. Все модели делай в нём. На GitHub это место **не загружай**.
3. Вкладка **View** → включи **Explorer**, **Properties**, **Output** и **Command Bar** (строка для кода внизу экрана).

**Как сделать модель:**
1. Gemini пишет скрипт. Скопируй его **целиком**.
2. Вставь в **Command Bar** и нажми **Enter**. Модель появится перед точкой появления и сразу будет выделена.
3. Если в **Output** появилась красная ошибка — скопируй её и отправь Gemini.
4. Хочешь что-то поменять — сделай 1–2 скриншота (спереди и сверху сбоку) и напиши Gemini, что не так. Он пришлёт новый скрипт целиком: вставляй так же, старая версия удалится сама.
5. Нравится — сохрани в файл: **Explorer** → **Workspace** → правый клик по модели → **Save to File…** → тип файла **`.rbxmx`** → имя строго как у модели (например, `prop_bench_01.rbxmx`).
6. Загрузи на GitHub: https://github.com/PUNU-1/roblox → папка `assets` → папка `models` → **Add file** → **Upload files** → перетащи файл → внизу **Commit changes**. Если файл с таким именем уже есть, он заменится новым.
7. Напиши владельцу, что модель загружена. Он проверит её в игре и отметит задание выполненным.

Модели ты утверждаешь сам, согласовывать с владельцем не нужно.

## Для Gemini: кто ты и как работаешь

- Ты делаешь **модели** для Roblox-игры. Код игры пишет Claude Code, не ты.
- Ты не видишь Roblox Studio и не имеешь доступа к файлам. Ты пишешь **скрипты на Luau**, которые строят модель из деталей. Друг вставляет их в Command Bar в Roblox Studio и присылает тебе скриншоты и ошибки.
- Делай только то задание, о котором попросил друг. Не придумывай лишних моделей.

### Ты — учитель: веди друга за руку

Друг **почти ничего не знает** о Roblox Studio и GitHub. Твоя задача — не только написать скрипт, но и подробно объяснить, что с ним делать, чтобы у друга всё получилось.

- **В начале первого чата** спроси, открыта ли Studio и включены ли Explorer, Properties, Output и Command Bar. Если нет — проведи друга по разделу «Подготовка Studio» выше.

Скажи, где модель появится и как к ней подлететь камерой: в Explorer открыть Workspace, кликнуть по модели и нажать клавишу **F**.

- Если задание неясно — спроси, а не угадывай.
- **Решения принимает владелец.** Если друг говорит, что владелец решил по-новому, а в этом файле ещё старое, не отказывайся работать: переспроси один раз, чтобы убедиться, и работай по новому решению. Владелец потом обновит файл.

### Правила скрипта (обязательно)

1. Один скрипт строит одну модель целиком. При каждой правке присылай скрипт **целиком**, а не кусок.
2. В начале скрипт удаляет из `workspace` старую модель с тем же именем.
3. Модель — один `Model` с именем строго из задания. Если нужен другой тип (например, `Accessory`), это будет сказано в задании.
4. Детали строишь вокруг точки (0, 0, 0): это **низ по центру** модели, если в задании не сказано иначе. **«Перед» модели смотрит в −Z.** В конце ставишь `model.WorldPivot = CFrame.new(0, 0, 0)` и переносишь модель в `CFrame.new(0, 0, -20)`, чтобы она встала перед точкой появления.
5. У всех деталей `Anchored = true` и гладкие поверхности (`Smooth`). Цвета задаёшь через `Color3.fromHex`.
6. Детали называешь понятно (`Leg1`, `Cushion`, `Frame`), а не `Part`.
7. В конце скрипт выделяет модель (`Selection:Set`) и печатает «Готово» и число деталей.
8. **Запрещено:** создавать `Script`, `LocalScript`, `ModuleScript`; использовать `InsertService`, `require` по номеру, `HttpService`, `loadstring`; бесконечные циклы и `wait`; брать модели из Toolbox. Всё строишь сам из деталей.

### Шаблон скрипта

Начинай каждый скрипт с этого шаблона и меняй только имя и детали:

```lua
-- prop_example_01 — что это за модель
local NAME = "prop_example_01"

local old = workspace:FindFirstChild(NAME)
if old then
	old:Destroy()
end

local model = Instance.new("Model")
model.Name = NAME

local function part(name, size, cframe, hex, material, className)
	local p = Instance.new(className or "Part")
	p.Name = name
	p.Size = size
	p.CFrame = cframe
	p.Color = Color3.fromHex(hex)
	p.Material = material or Enum.Material.SmoothPlastic
	p.Anchored = true
	p.TopSurface = Enum.SurfaceType.Smooth
	p.BottomSurface = Enum.SurfaceType.Smooth
	p.Parent = model
	return p
end

-- Детали. Точка (0, 0, 0) — низ по центру модели, «перед» смотрит в −Z.
part("Body", Vector3.new(2, 1, 2), CFrame.new(0, 0.5, 0), "#E8DCC4")

model.WorldPivot = CFrame.new(0, 0, 0)
model.Parent = workspace
model:PivotTo(CFrame.new(0, 0, -20))
game:GetService("Selection"):Set({ model })
print("Готово: " .. NAME .. ", деталей: " .. #model:GetDescendants())
```

Цилиндр или шар — обычная деталь со свойством `Shape` (`Enum.PartType.Cylinder`, `Enum.PartType.Ball`). Клин — `className` `"WedgePart"`. Сиденье — `"Seat"`. Картинка на детали — `Decal`. Надпись — `SurfaceGui` с `TextLabel` внутри (текст в игре только на английском).

### Стиль (для ВСЕХ моделей)

- **Мультяшный, яркий, low-poly**, плоские цвета, без фотореализма. В первые ночи в зале горит свет, а позже воры научатся его выключать. Поэтому важные объекты (Мона Лиза, камеры, ловушки) должны быть заметны и в полумраке.
- Простые, узнаваемые формы. Модель должна читаться издалека и сверху (вид с камеры наблюдения), в том числе в **чёрно-белом**: ночью камеры показывают ч/б картинку.
- **Палитра:** тёмно-синий `#1E2A44` (стены, ночь), бежевый мрамор `#E8DCC4` (пол, постаменты), золото `#D4A93A` (рамы), красный `#C8343A` (ловушки, лазеры, сигнализация), бирюза `#3BC6C1` (стекло, экраны). Можно брать оттенки этих цветов.
- **Материалы:** в основном `SmoothPlastic`. `Neon` — для того, что светится (лазеры, экраны, лампочки). `Glass` — для стекла. `Fabric` — для мягкого (обивка).
- **Меньше деталей — лучше.** Мелкий предмет — 10–30 деталей, а не сотни.
- `CanCollide` оставляй включённым у крупных частей. У мелких украшений можно выключить.

### Масштаб

- Всё в стадах. Персонаж Roblox ≈ 5 стадов ростом. Проёмы в зале — 8 стадов в ширину и 9 в высоту.
- Размеры из задания важны: карта рассчитана под них. Немного отличаться можно, сильно — нет.

## Что за игра

Рабочее название **Night Guard: Museum**, весь текст в игре на английском. Кооператив на 1–4 игроков. Игроки — ночная охрана музея. В зале висит **одна Мона Лиза**, всю ночь за ней приходят воры. Вор вынес картину — ночь проиграна. Продержались 5 минут — ночь выиграна.

- **Patrol** — бегает по залу, ловит воров.
- **Operator** — тоже ходит и ловит, но у него есть телефон с камерами и схемой музея. Пока телефон открыт, оператор не бегает и не ловит. Без оператора камеры видно только с пульта в дальней диспетчерской.
- Вор-**Карманник** в маске входит через один из 2–3 входов, снимает картину и бежит к ближайшему входу.
- Ловушка — **лазерная сетка**: ставится в отмеченные места, замедляет и подсвечивает вора.
- **Ночь за ночью воры сложнее и умнее.** Сначала обычные воры при включённом свете, их легко поймать. Потом приходят те, кто выключает свет, бьёт охранника или выключает камеры, а грабежи идут по хитрому плану: отвлечение, подделка картины, вор в форме охранника, подкоп. Против них команда покупает улучшения: лазерные сетки, сигнализацию на Мону Лизу и другое.

Полное описание — в `CLAUDE.md`.

Друг копирует файл из папки `src/` на GitHub и вставляет его в чат. Ищи:

1. Ошибки логики и баги.
2. Уязвимости для эксплойтеров — всё важное (поимка, кража, деньги, роли, батарейка фонарика) должно считаться **на сервере**, клиенту нельзя доверять числа.

6. Числа прямо в логике вместо `Config.luau`.

### [ ] Задание 2 — Мона Лиза `exhibit_monalisa_01`

Главный объект игры и **эталон стиля**: по ней делаются все остальные модели. Висит на стене посреди зала. Вор снимает её целиком и уносит в руках, поэтому стена в модель **не входит**.

- **Тип:** `Model` с именем `exhibit_monalisa_01`.
- **Размер:** 4.4 стада в ширину, 6 в высоту, глубина до 0.6. Картина **вертикальная**.
- **Точка привязки:** середина нижнего края **задней стороны** — там, где картина касается стены. То есть задник лежит на плоскости z = 0, а вся картина впереди него (z от 0 до −0.6). Картина смотрит в −Z.
- **Рама:** пышная золотая `#D4A93A`, толщина ~0.6 стада с каждой стороны. Ступеньками (внешний край толще и выступает вперёд, внутренний тоньше), украшения по углам (кубики или шарики), сверху посередине завиток или «ракушка». Можно взять 2–3 оттенка золота, чтобы ступеньки было видно в полумраке. До ~30 деталей.
- **Холст:** деталь `Canvas` примерно 3.2 × 4.8, чуть утоплена внутрь рамы. На передней стороне — `Decal` с именем `Painting`, `Face = Enum.NormalId.Front`.
- **Картинка:** мультяшная Мона Лиза. Её рисует и загружает в Roblox **владелец** и присылает другу номер картинки. В начале скрипта сделай переменную:
  ```lua
  local IMAGE_ID = 0 -- номер картинки от владельца
  ```
  Если `IMAGE_ID` равен 0, холст просто бежевый (`#E8DCC4`), а `Decal` не создаётся. Когда номер пришёл, друг вписывает его и запускает скрипт снова. `Texture` = `"rbxassetid://" .. IMAGE_ID`.
- **Сзади:** деревянный задник — коричневая доска во всю картину (например `#7A5230`, материал `Wood`). Золотая рама видна по краям.
- **Табличка:** маленькая золотая табличка внизу на раме, по центру (например 1.6 × 0.4). На ней `SurfaceGui` (`Face = Front`) с `TextLabel`: текст **`MONA LISA`**, тёмно-синий `#1E2A44`, без фона, крупно и чётко (`TextScaled = true`).
- **Готово, когда:** файл загружен в `assets/models/`, а владелец увидел в зале Мону Лизу с картинкой вместо жёлтого прямоугольника.

### [ ] Задание 3 — камера наблюдения `camera_wall_01`

Четыре такие камеры висят в углах зала на высоте 14 стадов и смотрят в зал наискосок и вниз. Оператор смотрит через них. Игроки должны сразу замечать камеру и понимать, куда она смотрит.

- **Тип:** `Model` с именем `camera_wall_01`.
- **Вид:** классическая мультяшная камера — прямоугольный корпус с козырьком сверху, круглый объектив спереди, кронштейн назад к стене.
- **Цвет:** корпус и козырёк **белые** (`#F2F2F2`), объектив тёмный (`#1E2A44` или почти чёрный, материал `Glass`), кронштейн и пластина серые.
- **Лампочка:** маленькая красная деталь `Led` (`#C8343A`, материал `Neon`) на корпусе спереди сверху. Мигать её заставит код, в модели она просто горит.
- **Детали по порядку, от стены вперёд:** пластина крепления (~1 × 1 × 0.2) → кронштейн (~0.3 × 0.3 × 0.8) → корпус (~1.2 × 1 × 2) с козырьком → объектив (цилиндр, деталь `Lens`, диаметр ~0.6). Передний край объектива примерно на z = −3. До ~15 деталей.
- **Точка привязки:** **центр задней стороны пластины** — то место, которым камера прикручена к стене (не низ по центру, как обычно). Пластина лежит на плоскости z = 0, вся камера впереди (z < 0), объектив смотрит в −Z.
- У всех деталей `CanCollide` выключен: камера висит высоко, её никто не задевает.
- **Готово, когда:** файл загружен в `assets/models/`, а владелец увидел в углах зала белые камеры вместо заглушек.

### [ ] Задание 4 — лазерная сетка `trap_laser_01`

Ловушка: игроки ставят её в проходах перед ночью. Вор, прошедший сквозь лучи, замедляется и подсвечивается. Модель — **только две стойки**, красные лучи между ними сделает код.

- **Тип:** `Model` с именем `trap_laser_01`. Внутри — две вложенные модели-стойки: `PostA` и `PostB`.
- **Расстановка:** `PostA` стоит в x = −4, `PostB` в x = +4 (между ними 8 стадов — ширина прохода). Лучи пойдут вдоль X, вор пересекает их вдоль Z.
- **Высота стоек:** 5 стадов — в рост человека.
- **Вид стойки:** техно-стойка. Круглая подставка (низкий цилиндр, диаметр ~1), тёмная металлическая труба (`#2A2F3A` или тёмно-синий `#1E2A44`, материал `Metal`), колпачок сверху. Можно красную или жёлто-чёрную полоску на подставке, чтобы стойку было видно.
- **Излучатели:** на каждой стойке **3 излучателя** `Emitter1`, `Emitter2`, `Emitter3` на высоте ~1, ~2.5 и ~4. Это маленькие красные детали (`#C8343A`, материал `Neon`), повёрнутые к другой стойке. Внутри каждого излучателя — `Attachment` с именем `Laser`, в той точке, откуда выходит луч. Код соединит `PostA.Emitter1.Laser` с `PostB.Emitter1.Laser` и так далее.
- **Точка привязки:** низ по центру — на полу посередине между стойками.
- `CanCollide`: у подставки и трубы включён, у излучателей выключен. Всего до ~25 деталей.
- **Готово, когда:** файл загружен в `assets/models/`. Пока сетку в игре ставить ещё нельзя (это сделает Claude позже), поэтому владелец проверяет её прямо в Studio.

### [ ] Задание 5 — маска вора `thief_mask_01`

Вор-Карманник — обычный блочный персонаж Roblox (R15) во всём чёрном, одежду сделает код. Ты делаешь только **балаклаву** — чёрную шапку-маску на всю голову. Больше ничего на голове нет. Картину вор несёт просто в руках, отдельная модель для этого не нужна.

- **Тип:** **`Accessory`** с именем `thief_mask_01` (не `Model`!). Это аксессуар, который надевается на голову персонажа.
- **Вид:** чёрная (`#151515`, материал `Fabric`) маска чуть больше головы, со скруглёнными краями (можно собрать из нескольких блоков). Спереди — горизонтальная **прорезь для глаз**: полоса телесного цвета (`#F5CDA8`) и на ней два чёрных глаза. Выглядит смешно, а не страшно.
- **Размер:** голова персонажа R15 примерно 1.2 × 1.2 × 1.2 стада. Маска — примерно 1.3 × 1.3 × 1.3, чтобы закрывала голову целиком.
- **Как устроить** (у аксессуаров свои правила, **не как у обычных моделей**):
  - Главная деталь называется строго **`Handle`** и стоит в центре головы (точка 0, 0, 0). Остальные детали прикрепи к `Handle` через `WeldConstraint`.
  - Внутри `Handle` — `Attachment` с именем **`FaceCenterAttachment`** в центре `Handle`. По нему Roblox сам совместит маску с центром головы.
  - У всех деталей **`Anchored = false`**, `CanCollide = false`, `Massless = true`. Иначе персонаж застрянет на месте.
  - Прорезь для глаз смотрит в −Z (туда смотрит лицо).
- **Скрипт:** в шаблоне вместо `Instance.new("Model")` будет `Instance.new("Accessory")`, а `WorldPivot` и `PivotTo` не нужны. Маска кладётся в `workspace` — оттуда её потом сохраняют в файл.
- **Проверка на манекене:** друг один раз вставляет стандартный манекен: вкладка **Avatar** → **Rig Builder** → **R15** (появится модель `Rig`). Если в `workspace` есть `Rig`, скрипт дополнительно надевает на него **копию** маски через `Humanoid:AddAccessory`, а старую копию сначала снимает. В файл сохраняется маска из `workspace`, а не копия с манекена.
- **Готово, когда:** файл загружен в `assets/models/`, а на манекене маска сидит ровно на голове.

Маленькая комната в конце длинного коридора, далеко от зала. Отсюда смотрят камеры, если в команде нет оператора с телефоном.

- **Вход:** проём посередине стены **+Z**, 8 стадов в ширину (x от −4 до 4) и 9 в высоту. К нему подходит коридор.
- **Пульт:** стол-пульт — **одна деталь** с именем строго **`ControlConsole`**, 10 × 3 × 3, центр в точке (0, 1.5, −3). Код будет искать её по имени. Сверху на нём (отдельными деталями):

- **Готово, когда:** файл загружен в `assets/models/`. Комнату в игру поставит Claude, когда она будет готова.
